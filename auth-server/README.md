# Auth Server

Centralized Identity Provider implementing the **OAuth 2.0 Authorization Code** grant.  
Renders its own Login and Registration UI; issues signed JWTs to trusted client apps.

---

## Tech Stack

| Concern | Library |
|---|---|
| Web framework | Express.js |
| Database | MongoDB + Mongoose |
| Password hashing | bcryptjs (12 rounds) |
| Session management | express-session |
| JWT signing | jsonwebtoken (HS256) |
| Input validation/sanitization | express-validator |
| Rate limiting | express-rate-limit |
| Security headers | helmet |
| Templating | EJS |

---

## Local Setup

### Prerequisites
- Node.js ≥ 18
- MongoDB running locally, or a free [MongoDB Atlas](https://www.mongodb.com/atlas) cluster

### 1. Install dependencies

```bash
cd auth-server
npm install
```

### 2. Configure environment

```bash
cp .env.example .env
```

Edit `.env` and fill in every value:

```env
MONGO_URI=mongodb://127.0.0.1:27017/auth-server

# Generate these with:  node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
JWT_SECRET=<64-char random hex string>
SESSION_SECRET=<different 64-char random hex string>

CLIENT_ID=client-app-1
CLIENT_SECRET=<shared with client-app>

ALLOWED_REDIRECT_URIS=http://localhost:3001/callback
ALLOWED_ORIGINS=http://localhost:3001

PORT=3000
NODE_ENV=development
```

> **Never commit `.env` to source control.** It is already in `.gitignore`.

### 3. Start

```bash
# Development (auto-restart on file changes)
npm run dev

# Production
npm start
```

Server starts on **http://localhost:3000**.

## OAuth 2.0 Endpoints

| Method | Path | Description |
|---|---|---|
| `GET` | `/authorize` | Begin authorization flow |
| `POST` | `/oauth/token` | Exchange auth code for JWT |
| `GET` | `/oauth/userinfo` | Retrieve user profile (Bearer token) |
| `GET` | `/login` | Login UI |
| `POST` | `/login` | Process login credentials |
| `GET` | `/register` | Registration UI |
| `POST` | `/register` | Process registration |
| `GET` | `/logout` | Destroy session |

### `/authorize` — Query Parameters

| Param | Required | Description |
|---|---|---|
| `client_id` | Yes | Must match a registered client |
| `redirect_uri` | Yes | Must exactly match `ALLOWED_REDIRECT_URIS` |
| `state` | Yes | Random CSRF token generated by client |
| `response_type` | Yes | Must be `code` |

### `/oauth/token` — Request Body

```json
{
  "grant_type":    "authorization_code",
  "code":          "<auth code from /authorize>",
  "client_id":     "client-app-1",
  "client_secret": "<CLIENT_SECRET>",
  "redirect_uri":  "http://localhost:3001/callback"
}
```

### `/oauth/token` — Response

```json
{
  "access_token": "<JWT>",
  "token_type":   "Bearer",
  "expires_in":   3600
}
```

## Security Notes

- **Password storage** — bcrypt with 12 salt rounds; plaintext passwords never persist.
- **Timing-safe login** — bcrypt is always called even when no user is found, preventing username enumeration via timing attacks.
- **Session fixation** — `req.session.regenerate()` is called on every successful login/register.
- **Redirect URI allowlist** — `redirect_uri` is validated against `ALLOWED_REDIRECT_URIS` before issuing any code. A mismatch returns `invalid_redirect_uri` immediately.
- **Single-use codes** — Authorization codes are marked `used: true` before the async DB lookup to prevent race-condition reuse. Reuse attempts delete the code and log a security warning.
- **Cookie flags** — `httpOnly`, `sameSite: lax`, and `secure` (production) on all session cookies.
- **Rate limiting** — 30 requests per 15-minute window per IP across all auth endpoints.

## Adding a New OAuth Client

Edit the `getClients()` function in `controllers/authController.js`, or extend it to read from a database collection for dynamic registration.

```js
'new-client-id': {
  clientSecret: process.env.NEW_CLIENT_SECRET,
  redirectUris: ['https://your-other-app.com/callback'],
  name: 'Another Client App',
},
```

Also update `ALLOWED_ORIGINS` in `.env` to allow the token exchange from the new client's origin.
